# План Карьеры в UE (S-73, без реализации)

Источник — замороженный веб (`nurtidev/boxing`, `web/src/engine/career.ts` 1628 строк, `world.ts` 207, `pro.ts` 603, `boxer.ts`
414, `stats.ts` 228, `simulate.ts` 346, данные `data/*.ts` ≈ 1150, UI `CareerHub.tsx` 1203 + `CreateBoxer.tsx` 371; идеи №5–11
CLAUDE.md основного репо). В UE сейчас: «Карьера — скоро» в главном меню (`UIMainMenu.cpp`), ядро боя на C++ с паритетом веба,
ростер 522 бойца (`Content/Boxing/Data/Roster.json`, экспорт `Tools/RosterExport` — статы уже выведены формулой веба).

## 1. Что такое Карьера в вебе (сжато)

| Блок | Веб | Суть для игрока |
|---|---|---|
| Создание бойца | `CreateBoxer.tsx`, `Boxer.createCustom` | имя, пол, вес, рост (размах — оценка), стиль, стойка, облик; старт ~18 лет, база ~50 |
| Ритм сезона | `Career`: 4 турнира/год, сборы без лимита с убывающей отдачей, `advanceYear` | год = сборы (рост статов по фокусу) + турниры; возраст и спад |
| Лестница любителя | `AMATEUR_EVENTS` (город → область → ЧК → Азия/Кубок/ЧМ/Азиада/ОИ), `stage`, `nationalRank` | сетки 2–6 боёв, медали → очки родословной; место в сборной подтверждается ЕЖЕГОДНО |
| Живой мир | `world.ts` `LivingWorld` (своя ветка ГСЧ) | соперники стареют, растут, уходят на пенсию, молодёжь; «один от страны» на международных |
| Олимпийский цикл | отбор (box-off) `startTrials/finishTrials`, путёвка `gamesTicket` | раз в 4 года — главный любительский пик |
| Звания | `titleStats`, `sportsTitle()` | 3-й разряд … КМС … МС … МСМК … ЗМС |
| Переход в профи | `canTurnPro/turnPro`, проекция amateur→pro (идея №11) | любительский потолок ≠ профи-класс; «зелёный» платит налог на дистанции |
| Профи-цепочка | `pro.ts` `ProCircuit`: топ-15 четырёх версий, пояса, Elo-сезон NPC, `evaluateOffer`, mandatory, стрип | предложения боёв, титульник строго 12 р., реабилитация после поражения, абсолютный чемпион |
| Мир профи | прогрев всех дивизионов с 1-го года, кэш по дивизионам, конверты любители→профи, пополнение до пола | пояса ходят и без игрока; бывшие соперники встречаются снова |
| Память | `faced`, `rivalRecord`, `chronicle`, `rosterSearch`, профиль | H2H, летопись, поиск по всем |
| Итог | `greatness()`, Зал славы | оценка величия, пик, лучшие победы |
| Анти-сейв-скам | `pending*`, слот при входе, гонг — точка невозврата | нельзя перезапуском переиграть сетку/бой |

В вебе карьера **не сохраняется** между сессиями (живёт в памяти вкладки) — сериализации нет, её придётся делать с нуля в любом варианте.

## 2. Объём «Карьера v1» — минимально интересный срез

Цель v1: **«от городского турнира до первого пояса»** — полный цикл любитель → профи → титульный бой, с сохранением, на одном весе.
Это то, ради чего игрок открывает Карьеру; всё прочее — глубина, которую можно добавлять, не ломая сейвы (версия сейва).

**В v1:**
1. Создание бойца: имя (генератор `names.ts`), пол, весовая (любительские категории), рост → размах (оценка), стиль, стойка, облик
   (`BoxerLook`: тон кожи/волосы/борода из готовых пресетов), превью в ринге. База — как `createCustom` веба.
2. Сезон любителя: сборы (фокус 1–2 стата, убывающая отдача), 4 турнира в год: город, область, ЧК, ЧА, Кубок мира, ЧМ (гейт по
   `nationalRank`, ЧК раз в год), сетки по `bracketRoundsFor`, соперники из живого мира (`buildOpponents` + квота «один от страны»),
   медали → родословная, `stage`/`nationalRank` с ежегодным подтверждением, спортивное звание.
3. Живой мир любителей — `world.ts` целиком (он маленький и даёт «живых» соперников; без него сетки — безликие филлеры).
4. Возраст и развитие: `ageOneYear`, `ageCurve`, `train`, `gainExperience`.
5. Переход в профи: проекция amateur→pro (скидка уровня у конвертов, налог на дистанцию у игрока — `proGreenFights`), выбор
   дивизиона один раз при переходе.
6. Профи — **один дивизион** (дивизион игрока): `ProCircuit` (4 версии × топ-15, чемпионы из ростера), `proCandidates`, предложение
   (`beltOptions`, `evaluateOffer`: риск-награда, «не котируешься», mandatory, титульник = 12 р., реабилитация), пояса, обязательные
   защиты и стрип, сезон NPC (`advanceSeason`: Elo-бои, пенсии, пополнение до `POOL_FLOOR`), новости года.
   **Упрощение прогрева:** вместо прогрева всех ~13 дивизионов с первого года — при `turnPro` строим цепочку дивизиона и прокручиваем
   `advanceSeason` за прошедшие годы (своя ветка ГСЧ, детерминировано): дивизион встречает игрока «прожитым», цена — доли секунды.
7. Бой карьеры: «Боксировать» (интерактив, тот же GameMode) или «Симулировать» (ядро в автопилоте, ~1 мс — как `PredictOutcome`);
   афиша — та же карточка, что в Выставке (вес боя, прогноз «при твоей игре»).
8. Сохранение: один слот, автосейв после каждого изменения; анти-сейв-скам как в вебе (сетка/бой персистятся до гонга, брошенный
   после гонга бой = поражение RSC, `advanceYear` сжигает недоигранное). «Продолжить карьеру» в главном меню.
9. Завершение: «Завершить карьеру» + итоговая карточка (рекорды, медали, пояса, пик) — без Зала славы.

**Отложить в v2+ (по ценности):**
| Что | Почему можно позже |
|---|---|
| Олимпиада/Азиада + отбор (box-off), путёвки | пик любителя, но 1 раз в 4 года и много правил (олимп. категории, сгонка к путёвке); v1 — ОИ нет |
| Смена веса: профи-дивизионы на выбор, кэш цепочек по дивизионам, стрип по всем кэшам, освоение веса (`acclimatizeWeight`) | v1 — один вес; сейв-формат сразу с картой дивизионов, чтобы не ломать |
| Конверты любители → профи (`graduateAmateurs`, `divisionForConvert`, гейт рейтинга `RANK_MIN_FIGHTS`) | без них пул держится пополнением до пола; «бывший соперник» в профи — приятная, но не ключевая деталь |
| Прогрев всех дивизионов с 1-го года, новости фоновых дивизионов | нужен только при смене веса |
| Память: `faced`, H2H, летопись, поиск «Все боксёры», профиль-модалка | глубина; данные (ids боёв) копим с v1, экраны — потом |
| Зал славы, `greatness()`, несколько слотов, статистика карьеры | косметика итога |

## 3. Архитектура в UE

### 3.1 Слои

```
CareerCore (чистый C++, без UObject, как ядро боя)   ← порт career/world/pro/boxer/stats.ts, свои ветки mulberry32
  FCareerBoxer (статы, физика, родословная, возраст, профи-рекорд)   FCareerWorld (LivingWorld)   FProCircuit   FCareer
UBoxingCareerSubsystem (GameInstanceSubsystem)       ← владеет FCareer; сейв/загрузка; API для UMG; запуск боя
UBoxingCareerSave : USaveGame                        ← версия + бинарный блоб FCareer (FMemoryWriter/Reader)
UMG-экраны (ux)                                      ← только через подсистему
ABoxingFightGameMode                                 ← бой карьеры как бой Выставки: FCareerBout → пресеты → FFightResult → подсистема
```

* **Порт 1:1** (логика с ветвлениями и константами баланса — переписывать «с нуля» нельзя, это выверенная спецификация):
  `stats.ts` (`deriveStats`, `ageCurve`, `agingOffset`, `frameWeight`, `estimateHeight/Reach`, категории), `boxer.ts` (`createCustom`,
  `overall`, `train`, `gainExperience`, `ageOneYear`, `fightProfile` с проекцией веса — часть уже есть в `FightProfile.cpp` — и
  скидкой amateur→pro, `proSeasoning/distanceSeasoning`), `world.ts`, `pro.ts` (`ProCircuit`, `evaluateOffer`, Elo `simBout`),
  из `career.ts` — события, `buildOpponents`, `medalFor`, ранг сборной, звания, сезон, предложения, `recordProBout`, mandatory/стрип.
* **Упростить/заменить:**
  - `simulateFight` (simulate.ts) **не портируем**: бои игрока (и «Симулировать») и редкие NPC-бои отбора идут **ядром боя в
    автопилоте** — правила UE (5 судей любителей, профи-досрочки S-61) одни для интерактива и симуляции; паритет ядра с simulate
    держится тестом (±0.12). NPC-сезон профи и так на Elo-логистике (`simBout` в pro.ts), не на simulate.
  - Ссылки на объекты (`Set<Boxer>`, `Map<Boxer, …>`, общий объект «живой боец = тот же после ухода в профи») → **стабильные
    `int32 Id`** бойцов и реестр `TMap<int32, FCareerBoxer>` в `FCareer`; карты рейтингов/рекордов NPC — по Id. Это и есть
    сериализация.
  - Летопись (`chronicle`) — в v1 не держим (только Id боёв в истории), строки генерируются при показе.
  - Тексты событий/новостей — коды + параметры (локализация, без склейки строк в ядре).
* **Данные:** расширить `Tools/RosterExport` — кроме выведенных статов писать сырые поля, нужные карьере: регалии (`Accolades` —
  для `pedigreePoints`/`amateurBase`), год рождения, флаг/страна, профи: дивизион, рекорд, пояса (`badge` разобранный),
  `proSeasoning`; генератор имён (`names.ts`: группы и доли) — в `Names.json`. Ростеры остаются «затравкой» живого мира, как в вебе.
* **Детерминизм:** те же ветки ГСЧ, что в вебе — основной `rng(seed)`, мир `seed ^ 0x9e3779b1`, джорнимены `seed ^ 0x5bd1e995`,
  сезон профи `seed ^ 0x85ebca6b`; состояние каждой ветки (uint32) — в сейве, поэтому загрузка продолжает ровно ту же карьеру.
  Сид боя — из основной ветки (как в вебе), бой воспроизводим по сиду. В TU CareerCore — `#pragma float_control(precise, on)`
  (S-73: модуль UE собирается с `/fp:fast`, без прагмы UE и харнесс расходятся). Межплатформенная бит-в-бит гарантия — нет
  (libm), сейв от этого не зависит (хранит состояние, а не сиды «для пересчёта»).
* **Сохранение:** `USaveGame` с `int32 Version` и `TArray<uint8> Blob`; `FCareer::Serialize(FArchive&)` пишет все поля по порядку
  (UE-архив, без JSON — компактно и быстро). Автосейв: после каждого изменения состояния (вход в событие, гонг, итог боя, год). Анти-
  сейв-скам: «бой начат» пишется в сейв ДО первого гонга; на загрузке незакрытый начатый бой = поражение RSC (как веб). Миграции —
  по `Version` (v2-поля с дефолтами).
* **Живой мир и цена:** мир ≈ 11 категорий × (10 KZ + 9 intl) ≈ 200 бойцов на пол + профи-дивизион ~25 — `advanceYear` микросекунды–
  миллисекунды; сейв — десятки КБ. Без потоков.

### 3.2 Бой карьеры

`UBoxingCareerSubsystem::StartBout(FCareerBout)` → тот же путь, что Выставка (`ApplyToFightMode`: проекция веса, раунды, правила
`bProRules = rounds > 3`, сид, `Seasoning` из `distanceSeasoning`) → `ABoxingFightGameMode` → `FFightResult` (победитель, метод,
раунд, карты) → `FCareer::ApplyBoutResult`. «Симулировать» — `FBoxingFightCore` с `bAiControlled` у обоих, без загрузки ринга
(как `PredictOutcome`, один бой). Итог боя в карьере — экран итога Выставки + плашка медали/пояса.

## 5. Этапы (UE-спринты) и оценка

Оценка — в спринтах студии (один прогон ролей; ориентир по прошлым: порт ядра боя S-41 + паритет ≈ 1–2 спринта).

| Спринт | fight-designer (ядро) | ux-mobile (параллельно) | QA |
|---|---|---|---|
| **К1** | экспорт данных (регалии, имена) + `FCareerBoxer`/stats/boxer + `world.ts`; харнесс: паритет с вебом (эталоны vite-node: `deriveStats`, `fightProfile`, `train` на сиде, 20 лет мира — сводка пула) | макеты экранов 1–3 на заглушке API подсистемы (интерфейс фиксируется в начале К1) | — |
| **К2** | любительский сезон: события, сетки, `buildOpponents`, медали, сборная, звания, сборы, `advanceYear`; сейв/загрузка; стресс-харнесс любителя | создание бойца, хаб (сезон, сборная), сетка | — |
| **К3** | бой карьеры (StartBout/ApplyBoutResult, «Симулировать», анти-сейв-скам), баланс любителя под живого игрока | афиша/итог в карьере, сводка года | плейтест любительского сезона |
| **К4** | профи: один дивизион, `ProCircuit`, предложения/`evaluateOffer`, пояса, mandatory/стрип, прокрутка сезонов при переходе; полный стресс 300 карьер | экраны «Профи» и предложения, завершение карьеры | — |
| **К5** | баланс полного цикла по плейтесту (время до пояса, доля медалей при «обычной игре»), миграция сейва v1 | полировка, геймпад | приёмка v1 |

**Итого v1 ≈ 5 спринтов** (ядро — весь путь; ux — с К1 параллельно). v2 (ОИ+отбор, смена веса и все дивизионы, конверты, память/
летопись/поиск, Зал славы, слоты) — ещё ≈ 3 спринта.

## 6. Риски

| Риск | Чем грозит | Что делаем |
|---|---|---|
| Объём `career.ts` (1600 строк правил: анти-фарм рейтинга, гейты, реабилитация, квоты) | тонкие баги, «тупики» (дебютанту все отказывают) | порт вместе с тестами веба (`career/pro/world/olympics/hype.test.ts` ≈ 1600 строк) как тесты харнесса; стресс 300 карьер с первого спринта |
| **Баланс: живой игрок слабее ИИ** | веб калиброван под `simulateFight` (ИИ vs ИИ), а живой игрок «при обычной игре» берёт на 15–25 п. меньше (S-65) → медали/пояса недостижимы, карьера скучна | стресс-харнесс играет за игрока **ботом average** (`FFightBot`) через ядро; цели: медаль ЧК к ~21–22 годам у «обычной игры», первый титульник к ~27–29; правим `tier` филлеров и окно сложности сеток, а не ядро боя |
| Правила UE ≠ веба (5 судей любителей, профи-досрочки S-61, углы) | цифры карьеры веба не переносятся 1:1 | паритет — только для частей без боя (мир, статы, Elo-сезон); исходы боёв сверяем распределениями |
| Длительность | бой 3–12 мин × десятки боёв в год → прохождение на сотни часов | «Симулировать» для любого боя; по умолчанию руками — только медальные/титульные бои (решение владельца) |
| Сейв | object identity веба, новые поля в v2 | Id вместо ссылок с первого дня; `Version` + миграции; тест «сохранил — загрузил — продолжил = без сейва» |
| Детерминизм | `/fp:fast` UE, libm на iOS/ARM | прагма precise (S-73); не обещать межплатформенный реплей по сиду |
| Мобильные | экраны хаба плотные | ux закладывает портрет с К1 (как веб-версия) |

## 7. Проверка

* **Харнесс CareerCore** (как `Tools/CoreHarness`: заглушка CoreMinimal, MSVC/clang/gcc, CI): заглушку расширить минимальными
  `FString/TMap/TSet` поверх std (или писать ядро на `TArray` + сортированных массивах — решим в К1 по объёму).
* **Паритет с вебом** (vite-node, как `webref.ts`): детерминированные функции без боя — `deriveStats` по ростеру, `fightProfile` (вес +
  amateur→pro), `train/gainExperience/ageOneYear` на фиксированной последовательности ГСЧ, `LivingWorld` за 20 лет (размер пула,
  средний уровень по категориям, пенсии), `ProCircuit.advanceSeason` 10 сезонов (смены поясов, рейтинги топ-15) — бит-в-бит или
  с допуском 1e-9.
* **Стресс** — порт `test/stress.test.ts`: N = 300 карьер на разных сидах (пол, вес, стиль), бот играет «как UI» (вход в событие →
  бои → итог; сборы; переход в профи; предложения) до пенсии; после каждого шага — инварианты (`nationalRank ∈ {null,1,2,3}`, рекорд
  целый ≥ 0, пояса без дублей, undisputed ⇔ 4 пояса, рейтинги конечны и в [55, 95], звание из списка, нет «тупика» профи-старта,
  нет утечки бойцов из мира). Плюс **сейв-фаззинг**: на случайном шаге сохранить → загрузить → продолжить; итог карьеры обязан
  совпасть с прогоном без сейва (детерминизм веток ГСЧ).
* **Баланс** — сводка стресса с ботом average/novice/strong за игрока: распределение медалей по возрасту, доля дошедших до профи и
  до пояса, возраст первого пояса — таблица в этом документе, приёмка QA плейтестом.
* **UE**: automation-тесты подсистемы (создать → год → сейв → загрузка), сценарий `-BoxUiScript` по экранам Карьеры.

## 8. Вариант «быстрее»: переиспользовать TS-движок вместо порта

| Вариант | ПК | Мобильные (iOS/Android) | Честная оценка |
|---|---|---|---|
| **Node-процесс рядом с игрой** (esbuild-бандл движка веба, JSON-RPC по stdin/stdout) | работает; интеграция ≈ 1 спринт | **нет**: на iOS нельзя запускать сторонний процесс/рантайм Node, на Android — непрактично | +40–80 МБ рантайма, антивирусы, консоли — нет; годится как **инструмент баланса** для дизайнера, не для релиза |
| **Встроенный JS** (плагин Puerts — V8/QuickJS в UE, open source; либо голый QuickJS) | работает | возможно: iOS — без JIT (V8 jitless / QuickJS), производительности карьеры хватит (вычислений мало) | интеграция 1–2 спринта + сборка TS→JS в Content; постоянный долг: два языка, отладка через границу, совместимость плагина с каждой версией UE, +5–25 МБ |
| **Порт на C++** (этот план) | да | да | ядро ≈ 4 спринта (К1–К4 по ядру), но без рантайма и с одним языком |

Почему переиспользование экономит меньше, чем кажется:
1. **UI — большая часть работы в любом варианте** (экраны 1–11), а он всё равно на UMG.
2. **Сериализации в вебе нет** — Id вместо ссылок и сейв писать в любом варианте (на TS или C++).
3. **Бой**: карьера веба зовёт `simulateFight` (TS) — а в UE бой другой (5 судей любителей, профи-досрочки, углы). С JS-карьерой
   либо два движка боя (симуляция TS ≠ интерактив C++), либо мост «JS → C++ ядро» на каждый бой — сложнее порта.
4. Веб **заморожен**, UE-правила уже разошлись с ним; дальнейшая жизнь карьеры (баланс под живого игрока, ОИ, мобильные) — в UE.

**Рекомендация:** порт на C++ по плану (v1 ≈ 5 спринтов). Node-процесс — опционально как песочница баланса (стресс-сравнение «веб
против UE» уже есть по схеме `webref.ts` через vite-node, отдельный рантайм для этого не нужен). Встроенный JS имеет смысл, только
если владелец хочет оставить веб живой «главной» реализацией правил, — сейчас решение обратное (2026-10-02).
