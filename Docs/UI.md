# Оболочка игры: меню, Выставка, HUD, итог (S-55)

Порт `web/src/App.tsx` (Выставка) и HUD интерактива на UMG. Все экраны — **C++-виджеты без WBP-ассетов**
(`UUserWidget`, дерево собирается в `NativeOnInitialized` через `WidgetTree->ConstructWidget`): их не нужно
открывать в GUI-редакторе, а сборка и правка — обычный C++.

## Поток

`L_Menu` (стартовая карта, `GameDefaultMap`) → главный экран → «Выставка» → выбор пары и раундов → «В бой!» →
`L_Ring` (бой с выбранными статами) → экран итога → «Реванш» (та же пара, новый сид) / «В меню».
«Быстрый бой» — случайная равная по весу и уровню пара любителей.

## Данные ростера

* `Tools/RosterExport/export.mjs` — Node-скрипт: бандлит `entry.ts` esbuild'ом из `node_modules` веба (алиас
  `@web` → `boxing/web/src`), **импортирует движок web как есть** (`Boxer.fromData`, `buildProRoster`, `buildLegends`,
  `fightProfile`) и пишет `Content/Boxing/Data/Roster.json`. Формулы вывода статов не копируются — правка баланса в
  web + перезапуск скрипта = новые статы в UE.
  ```
  node Tools/RosterExport/export.mjs                      # web рядом: ..\boxing\web
  node Tools/RosterExport/export.mjs --web <путь к web> --out <файл>
  ```
  Нужен `npm install` в web (esbuild). Node 24 подходит; если упрётся в версию — `npx -y -p node@22.23.2 node …`.
* Поля строки: `id` (`<kind>:<имя>`), `name`, `kind` (amateur/pro/legend), `gender`, `countryCode` (ISO из
  эмодзи-флага — шрифты UE эмодзи не рисуют), `country`, `city`, `age`, `weightKg`, `division`, `heightCm`, `reachCm`,
  `stance`, `style`/`styleLabel`, `stats` (7 статов, выведенных из регалий), `overall`, **`proStats`/`proOverall`/
  `proSeasoning`** (проекция `fightProfile(вес, pro=true)`: у любителя — скидка на необстрелянность, идея №11 веба),
  `badge`, `proRecord`, `accolades` (`accSummary`), `notes`. Сейчас 522 бойца: 103 любителя, 413 профи, 6 легенд.
* В рантайме JSON читает `UBoxingGameInstanceSubsystem` (`FRosterBoxer`). DataTable не делался: JSON читается
  без редактора и без переимпорта; для сборки он кладётся как есть (`DirectoriesToAlwaysStageAsNonUFS=Boxing/Data`
  в `DefaultGame.ini`).

## Передача пары в бой

`UBoxingGameInstanceSubsystem` (GameInstance-подсистема, свой GameInstance-класс не нужен) хранит
`FExhibitionSetup` (ид красного/синего, раунды, профи-правила, сид, вкладка/пол). `ABoxingFightGameMode::InitGame`
зовёт `ApplyToFightMode` (единственная правка GameMode): есть выбор — `RedPreset`/`BluePreset`/`Rounds`/
`bAllowDraw`/`Seed` из него, нет (L_Ring открыт напрямую, PIE) — свои пресеты. Командная строка (`-BoxSeed` и др.)
читается после и по-прежнему главнее.

Правила как в web: любители — 3 раунда, ничьих нет, сырые статы; профи/легенды — авто-раунды (чемпион vs
чемпион → 12, иначе 10) или 4/6/8/10/12, ничья возможна; при раундах > 3 бой идёт на `proStats` +
`Seasoning = proSeasoning` (налог на дистанцию у необстрелянного любителя).

Без меню: `-BoxPickRed=<часть имени> -BoxPickBlue=<часть имени> [-BoxPickRounds=N]` — та же пара сразу в L_Ring.

**HUD боя:** панели углов (полоса угла, имя, ISO-код страны, здоровье с числом и цветом по уровню, стамина —
мигает красным на пустом баке, «нокдаунов: N»), по центру раунд и часы (≤ 10 с — жёлтые), баннер нокдауна
(счёт крупно; свой нокдаун — «жми удары или блок» + полоса подъёма), перерыва и конца боя; подсказки по ситуации
игроку (нет сил, блок слабеет, угол открыт, канаты/угол); легенда управления клавиатура + геймпад (F1 —
скрыть); в автопилоте вместо неё плашка «АВТОПИЛОТ». **Итог:** через 3.5 с после конца боя (`ResultDelay` —
дать доиграть нокаут), «ПОБЕДА / ТЫ ПОБЕДИЛ / ПОРАЖЕНИЕ / НИЧЬЯ», победитель, метод (нокаут/RSC с раундом,
вид решения), карты трёх судей по раундам и итог (цвет — чей раунд), нокдауны по раундам; ввод переключается
на UI, фокус на «Реванш» (Enter / A).

**Масштаб и ввод.** Размеры заданы для 1920×1080; DPI-кривая UMG (по короткой стороне) даёт на 1440p ×1.33 —
пропорции те же (см. скриншоты 1080/1440). Мышь, клавиатура (стрелки/Tab + Enter) и геймпад (крестовина + A):
наведение/фокус — светлая рамка кнопки.


аргумент режется по пробелу), `-BoxUiRounds=N` (профи), отладка нокдауна — `-BoxUiDebugChin=N` /
`-BoxUiDebugChinRed=N` (подбородок синего/красного). Без `-BoxAutopilot` красный — игрок (виден HUD с легендой).

## Навигация (все экраны)

* Фокус виден: у кнопки в фокусе — **золотая рамка 3 px** (у `SButton` нет кисти фокуса, только наведения; база экранов
  `UBoxingUiWidget` отслеживает фокус каждый тик и подменяет стиль). Мышь — по-прежнему светлая рамка наведения.
* Стрелки / крестовина / левый стик — геометрическая навигация Slate; Enter / A — нажать; **Esc / B — назад**
  (`HandleBack`: Выставка → меню, настройки → закрыть, пауза → подпанель → продолжить); Start на паузе — продолжить.
* Потерянный фокус возвращается на ту же кнопку по ключу (`Track/FocusKey`): строка ростера после выбора (список
  пересобирается), вкладки, раунды; только что открытый экран встаёт на свою кнопку по умолчанию.
* Экран под настройками (главное меню / пауза) на время настроек **неактивен** — иначе навигация Slate уходит
  стрелкой на его кнопки и A нажимает их «за спиной» (поймано сценарием: настройки → «вниз» → нажался «Быстрый бой»).
* Настройки: ←→ / крестовина вбок на строке — изменить (перехват в `NativeOnPreviewKeyDown`: иначе кнопка сама
  превращает стрелку в навигацию), Enter / A — следующее значение по кругу, стрелки ‹ › справа — для мыши (не фокусируются).
* Список Выставки прокручивается за фокусом (`SetScrollWhenFocusChanges`).

# Прогноз пары (для UI, S-61)

Ядро (fight-designer) даёт три вещи; карточку Выставки рисует ux-mobile. Все функции — `FightProfile.h` (namespace
`BoxingFightProfile`, только CoreMinimal) и обёртки `UBoxingGameInstanceSubsystem`.

| API | Что |
|---|---|
| `UBoxingGameInstanceSubsystem::RingWeightKg(Red, Blue, bProFight)` | вес боя: середина пары → ближайшая реальная категория (любители — `AMATEUR_CLASSES_M/F` = WEIGHT_CLASSES веба, профи/легенды — веса дивизионов ростера своего пола) |
| `BoxingFightProfile::WeightStretch(ring, red, blue)` | макс. отклонение веса бойца от веса боя, кг: ≤ 4 — реальный бой, ≤ 8 — кэтчвейт-натяжка, ≤ 14 — бой мечты, дальше — фэнтези (realismTag веба) |
| `BoxingFightProfile::ProjectToWeight(setup, кг)` | боец на весе боя (fightProfile веба): статы после сгонки/набора + `MassForPower/DurabilityMass` |
| `UBoxingGameInstanceSubsystem::ForecastPair(Red, Blue, Rounds, bProRules)` → `FPairForecast` | вес боя, сгонка/набор каждого (`RedDelta/BlueDelta`, > 0 — сгоняет), `Stretch`, `Odds`; кэш по паре/раундам/правилам |
| `BoxingFightProfile::PredictOutcome(red, blue, rounds, bPro, N = 60)` → `FOutcomeOdds` | «честный» прогноз: N боёв ядра ИИ против ИИ (раунд 55 с, без постановки, шаг 0.05 с, фиксированные сиды — детерминировано, половина боёв со сменой углов); `RedWin/BlueWin/Draw`, `RedStoppage/BlueStoppage` (доля боёв, выигранных досрочно), `KnockdownsPerFight` |

* Бой из Выставки идёт ровно с той же проекцией, что в прогнозе: `ApplyToFightMode` ставит в пресеты `Stamina/Chin` после
  проекции, `MassForPower/DurabilityMass` и `RingWeightKg` (для надписи «вес боя N кг» в HUD/итоге).
* `Odds` — про автопилот (ИИ против ИИ), не про конкретного игрока: «кто сильнее по ядру» с учётом веса, размаха, стиля и
  профи-правил. **Живой игрок выигрывает заметно реже** (QA UE-3: Алимханулы–Нурсултанов 62% против 36% у бота average) — ИИ за
  красного играет ровно и реагирует на каждый замах. Поэтому подпись этой цифры — не «твои шансы», а нейтральная («по силам»,
  «если бы дрались ИИ»); «твои шансы» — `PlayerForecast` ниже.
* Стоимость: ≈ 0.5 мс на 10-раундовый бой (харнесс, /O2) — 60 боёв ≈ 30–70 мс на первом выборе пары, дальше из кэша. Звать по выбору пары/раундов,
  не каждый кадр.
* Цифры для QA-пар (вес боя, прогноз ядра): Головкин–Фьюри 90 кг — Головкин 15% (досрочно 15%), Фьюри 85% (досрочно 72%);
  Шилдс–Маршалл 76 кг — 40 / 52%, ничья 8%; Гадфа–Вейтия 75 кг — 97 / 3%; Ташкенбай–Бибосинов 50 кг — 75 / 25%.

|---|---|
| `UBoxingGameInstanceSubsystem::PlayerForecast(Red, Blue, Rounds, bProRules)` → `const FPlayerForecast*` | `nullptr` — ещё считается (первый вызов на ключ запускает расчёт в пуле потоков; звать можно каждый тик, повторно не запускает); дальше — указатель на кэш (живёт, пока жива подсистема) |
| `FPlayerForecast::bValid`, `Ms` | готово; сколько считалось в фоне, мс |
| `FPlayerForecast::Odds.Average` | **«обычная игра»** — главная цифра: бот average за игрока (красный), 150 боёв, 95% ДИ ≈ ±8 п. |
| `Odds.Novice` / `Odds.Strong` | края диапазона «новичок … сильный игрок», по 60 боёв (±12 п.) |
| у каждого (`FOutcomeOdds`) | `RedWin` — шанс игрока, `BlueWin`, `Draw` (профи), `RedStoppage`/`BlueStoppage` — досрочно, `KnockdownsPerFight`, `Fights` |

* Расчёт: `BoxingFightProfile::PredictForPlayer` — тот же вес боя и проекция, что `ForecastPair`/бой; бот — `FFightBot` автоплейтестов
  (`-BoxBot`), игрок всегда красный, раунд 55 с (бой Выставки). Цена ≈ 0.3–0.8 с на 3 р., ≈ 0.6–1.4 с на 10 р. (в фоне, кадр не стоит).
* Подписи (честно): `Average.RedWin` — «твои шансы при обычной игре ≈ N%», диапазон — «от A% (новичок) до B% (сильная игра)»;
  `Odds` из `ForecastPair` — «по силам (ИИ против ИИ) N%». Пока `nullptr` — «считаем…», без цифры. Для любителей `Draw` всегда 0.
* Сверка с бот-сериями (Docs/FIGHT_CORE_PORT.md, S-65): average-прогноз в пределах ДИ факта на всех 9 парах QA, например
  Алимханулы–Нурсултанов — ИИ vs ИИ 62%, при твоей игре 45% (новичок 12%, сильный 77%); Ташкенбай–Бибосинов — 78% / 66% (38…87%);
  Балкибекова–Кызайбай — 68% / 44% (5…70%).

## Итог боя: судьи (S-65)

* `FFightResult::NumJudges` (и `FFightSnapshot::NumJudges`): любители — **5 судей** (World Boxing п. 6.1.2), профи — 3. Массивы
  `JudgeTotals`/`FRoundResult::JudgeCards` — на `MAX_JUDGES` = 5, читать первые `NumJudges`. `UIFightResult` уже рисует `NumJudges`
  колонок (точечная правка fight-designer, на 1920×1080 влезает) — проверить в узком окне/портрете (ux).
* Любители: в раунде ничьих нет (10-9 / 10-8 / 10-7). Подписи: `Unanimous` — все судьи за одного («Единогласное решение судей»),
  иначе `Split` («Раздельное решение судей»: 3:2, 4:1, а также 4 или 3 при ровных картах). «Большинством» у любителей не бывает
  (в регламенте такого нет); `Majority`/`Draw*` — только профи (3 судьи, 2 за одного и ничья у третьего). `TieBreak` не выдаётся.
* `FFightResult::TieNominee[j]` (−1 / 0 / 1): у судьи равная сумма (только при 10-8), и по п. 9.1.5 он назвал победителя — можно
  показать «28 – 28 ▸ Ташкенбай» (ux).

# S-63: загрузка боя, качество, честные разрешения, мелочи

## Загрузка: было → стало

Было (плейтест UE-2, `qa-ue/logs/rematch5.log`): каждый «В бой» / «Реванш» — `LoadMap(L_Ring)` 12.7–16.1 с замершего
кадра + ~2.8 с до первого кадра. Причины: GameMode синхронно грузил BP_Boxer (AnimBP GASP → базы Motion Matching
PoseSearch, MetaHuman), облики, грумы; после боя LoadMap собирал мусор — следующий бой грузил всё заново.

Стало (`UBoxingGameInstanceSubsystem`, раздел «Загрузка боя»):
1. **Предзагрузка в меню** — `StartFightPreload` (из `ABoxingMenuGameMode::StartPlay`): асинхронно (`FStreamableManager`)
   BP_Boxer, BP_Referee, ретаргетер и всё из `/Game/BoxingLocal/Characters` (облики + грумы), `/Game/BoxingLocal/Anim`,
   `/Game/Boxing/{Anim,Audio,Input,Characters}` — 216 ассетов; новые ассеты в этих папках подхватываются сами. Бюджет
   `s.AsyncLoadingTimeLimit` — 25 мс/кадр в меню, 150 мс на экране загрузки, после — штатный.
2. **Удержание между картами** — `KeepLoadedAssetsResident` на `PreLoadMap`: верхнеуровневые объекты загруженных
   пакетов `/Game/` (не карты, не `__External*`, не акторы/компоненты/мир) — в `Resident` (≈ 4000 объектов, 2–6 мс).
   Сборщик мусора LoadMap их больше не выгружает → реванш и повторный бой не грузят ничего.
3. **Экран загрузки** — `UBoxingLoadingWidget` (`UILoading.*`): углы и имена, «Любители/Профи · N раундов · вес боя»,
   честная полоса предзагрузки («Загружаем бойцов и арену… N%» → «Выходим на ринг…»), совет по управлению
   (клавиатура + геймпад, случайный из 7). Показывается сразу по «В бой»/«Реванш»/«Быстрый бой» (ввод экрана под ним
   отключён), OpenLevel — когда предзагрузка готова. На сам LoadMap — тот же экран на Slate через MoviePlayer
   (`BoxLoading::MakeSlate`, свой поток, индикатор), после карты — снова UMG-экран поверх первых кадров (прогрев PSO),
   снимается, когда кадр < 0.25 с (≥ 3 кадров, не позже 10-го / 20 с).
4. Лог: `LOAD: …` — от нажатия до карты и до первого кадра, удержание, предзагрузка. Флаги: `-BoxNoPreload`,
   `-BoxNoLoadingScreen` (без MoviePlayer), `-BoxLoadFlush` (A/B: не ждать предзагрузку — LoadMap догружает синхронно;
   оказалось медленнее: 20.7 с против 17.6 с).

Замеры (1920×1080 -ForceRes, офскрин; машина делилась с другими ролями — разброс ±30 %), «от нажатия до первого кадра боя»:

| Сценарий | Было | Стало |
|---|---|---|
| Реванш | 15.8 с (LoadMap 12.7–13.1 с) | **0.43–1.9 с** (LoadMap 0.28–0.74 с), 5 замеров |
| «В бой» из меню, ассеты уже в памяти (≥ ~20 с в меню или второй бой) | ~16.6 с | **0.3–0.74 с** |
| «В бой» сразу после запуска (холодно) | ~16.6 с замершего кадра | 8.7–17.6 с **с экраном загрузки и прогрессом** |
| Предзагрузка целиком от запуска игры | — | 18.6–21.4 с (в фоне, меню живое) |

Холодный «В бой» за < 5 с не достигнут: асинхронная загрузка в редакторной сборке (-game, uncooked, DDC) не быстрее
синхронной; это закрывается тем, что игрок обычно дольше 20 с выбирает пару в Выставке. В cooked-сборке (pak, без DDC)
цифры должны быть заметно меньше — не мерено.

## Качество графики

* Пресет определяется по группам Scalability **без** `sg.ResolutionQuality` (штатный `GetOverallScalabilityLevel`
  требовал совпадения и разрешения — при `ResolutionQuality=0` в общем ini писал «Своё», хотя всё «эпик»).
* Выбор пресета ставит разрешение рендера: высокое/эпик — **100 %**, среднее — 85 %, низкое — 70 % (было: значение из
  `PerfIndexValues`, 2 / 87 %; при 0 — `r.ScreenPercentage.Default` = 72.9 %, 1400×788 на 1080p).
* Новая строка **«Разрешение рендера»**: Авто (движок) / 50…100 %. Общий ini при старте не трогается — «Авто» остаётся
  авто, пока игрок не выберет. **Внимание tech-artist:** замеры FPS «1080p эпик» до S-63 шли на 72.9 % рендера; при
  100 % нагрузка выше.

`-RenderOffscreen -windowed -ResX/-ResY` без **`-ForceRes`** давали окно 888×500 (все прежние `ui_1080`/`ui_1440`
были 888×500). **Флаг `-ForceRes` обязателен** в любом скриншотном прогоне. Пересняты на 1920×1080 и 2560×1440:

(меню, Выставка, настройки с новой строкой, HUD, пауза, итог, загрузка) помещается без обрезки на обоих.

# S-67: холодный старт, разрешение по умолчанию, нокдауны, память, два прогноза

## Холодный старт

* **Арена за меню — сразу.** Фон (`L_Ring` экземпляром уровня) и предзагрузка боя шли одной очередью асинхронной загрузки,
  предзагрузка — с высоким приоритетом, и меню ~18 с стояло на чёрном фоне. Теперь `ABoxingMenuGameMode` зовёт
  `StartFightPreloadAfter(фон)`: предзагрузка стартует, когда фон показан (`IsLevelVisible`, не позже 8 с), бюджет фона 60 мс/кадр.
  Лог `LOAD: фон меню показан через X с`. Было: арены нет и на 5.8 с (`ui4_menu_before_*`); стало: **0.5–1.7 с** после карты
  меню (≈ 8–14 с от старта процесса, из них 7–12 с — запуск редакторной `-game`), `ui4_menu_after_*`.
* **Надписи движка** «Preparing Textures/Animation Sequences (N)» (и прочие map warnings) — `GEngine->bSuppressMapWarnings`
  в `Initialize` подсистемы (в Shipping их и так нет). `-BoxMapWarnings` — показать. `AddOnScreenDebugMessage` не тронут.
* **Предзагрузка кусками** (`PreloadQueue`, лог `LOAD: кусок «…» (N) — X с`): ядро (BP_Boxer, ретаргетер, папки анимаций/ввода/звука/
  `Boxing/Characters`) → рефери → облики по одному → грумы и кожа. По «В бой» до конца очереди догружается только пара
  (`PairAssetPaths`: облики углов по правилам `VisualPathFor`, рефери и его облик, грумы/текстуры кожи из `Appearance.json`),
  остальные облики — при следующем входе в меню. Реванш не добирает отложенное (иначе — по облику на бой, см. «Память»).
  Под непрозрачным экраном загрузки мир не рендерится (`SetWorldRendering`), снова — в `OnPostLoadMap` (прогрев PSO).
  Флаги замеров: `-BoxPreloadEarly` (как S-63 — сразу со стартом), `-BoxPreloadAll` (не отбрасывать облики), `-BoxMenuBudget=`/
  `-BoxLoadBudget=` (мс/кадр), `-BoxLoadRenderWorld`.
* **Куда уходит время** (по кускам, офскрин 1080p): `BP_Boxer` — **18–37 с из 19–42 с** всей предзагрузки (в зависимости от загрузки
  машины другими ролями), всё остальное (облики, грумы, анимации ударов, звук) — 2–4 с. BP_Boxer тянет AnimBP GASP со **160 базами
  Motion Matching** (прыжки, присед, спринт, паркур…) и ~1280 AnimSequence с редакторными данными (FKControlRig, MovieScene) —
  боксёру нужны лишь стойка/шаги/развороты. Бюджет загрузки за кадр время не меняет (25 → 70 мс в меню: 34 с vs 37 с; 150 → 400 мс
  на экране загрузки: 30–34 с vs 29 с) — упор в загрузку/постобработку ассетов, не в кадр. **Главный рычаг — урезанный AnimBP/
  chooser без лишних баз (зона game-feel/tech-artist)** и cooked-сборка (нет редакторных данных анимаций); DDC уже тёплый
  (zen local, `PoseSearch … BuildIndex From Cache`), PSO-прогрев первого кадра — 0.3 с.

Замеры «В бой» сразу после старта (быстрый бой на 8-й секунде меню), от нажатия до первого кадра боя:

| Сценарий | Было (S-63) | Стало |
|---|---|---|
| Арена за меню | нет и через 5.8 с (чёрный фон) | 0.5–1.7 с |
| Холодный «В бой», машина занята (другие роли гоняют UE) | 31.5 с (`-BoxPreloadEarly -BoxPreloadAll`, тот же час) | 29.5–34 с |
| «В бой» на 11-й секунде меню, машина свободна | — | 6.2 с (предзагрузка ядра 19 с от старта) |

Честно: цель «холодный "В бой" заметно быстрее 18 с» в моей зоне **не достигнута** — время почти целиком BP_Boxer (см. выше);

## Прогноз пары: два честных прогноза

Карточка Выставки: **«Твои шансы при обычной игре ≈ N%»** (`PlayerForecast(...)->Odds.Average`, бот-игрок за красного против ИИ), справа
«соперник M%» (профи — и «ничья»), полоса, строка «от A% (новичок) до B% (сильная игра) · ты в красном углу, бот-игрок против ИИ».
Пока считается в фоне — «считаем…» без цифры (блок той же высоты, `FillPlayerOdds` из `NativeTick`). Ниже одной строкой
**«По силам (ИИ против ИИ): красный X% · синий Y% · досрочно … · нокдаунов за бой …»** (`ForecastPair.Odds`, переносится в узком
окне). Карточка влезает на 1080p/1440p/720p без обрезки «В бой!» (`ui4_1080_exhibition`, `ui4_1440_exhibition`, `ui4_720_exhibition`).

## Поиск бойца по имени

`FindByName` — лучшее совпадение, а не первое по подстроке: полное имя > целое слово (фамилия) > начало слова > подстрока
(было: `Головкин` на вкладке «Профи» не находился, и сценарий брал сильнейшего из списка — Энниса). Сценарий `-BoxUiPick`: нет на вкладке —
ищет по всем вкладкам (с предупреждением в логе); `-BoxPickRed/Blue` и так искали по всем.
