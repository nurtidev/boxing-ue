## 2. Исправление: удар/уклон вне фазы боя (`BoxerCharacter::ApplyFightState`)

**Было.** В нокдауне ядро не тикает бойцов: удар атакующего «замерзает» с фазой, упёртой в 1. Детектор нового
удара считал старт как `CoreTime − Phase × Dur`, эта оценка ползла с часами, и `OnPunchStarted` срабатывал
~30 раз/с весь счёт (перезапуск монтажа удара, рывки в конечной позе, стойка не включалась). В перерыве
застывали удар/уклон и `FightTargetVelocity` (боец «дрейфовал» и не вставал в стойку).

**Стало.** Вне `EFightPhase::Fighting` удар и уклон для анимации — выключены (монтаж плавно уходит в стойку),
скорость слежения — 0. Новый удар определяется по абсолютному моменту контакта
(`CoreTime + PunchTimeToContact`), он постоянен весь цикл удара.

**Проверить** (`L_Ring`, автопилот, `-BoxPhysHits=0`):
- [ ] нокдаун: у уронившего монтаж удара плавно уходит (blend-out) из позы контакта в стойку, без дёрганий; в логе
      нет потока `OnPunchStarted`. Если уход из контакта выглядит обрубленным — вместо стопа доигрывать отход по времени;
- [ ] перерыв: оба стоят в стойке, не ползут;
- [ ] обычный бой: каждый удар запускает монтаж ровно один раз (серии джебов тоже).

### Результат (S-41 game feel, 02.10.2026): причина найдена — вариант H1, гонка с параллельной оценкой позы

Без отладочных символов стек разобран так: базы модулей — из потока ModuleList минидампа
(`Saved/Crashes/*/UEMinidump.dmp`, разбор PowerShell-скриптом), адреса → ближайший экспорт `UnrealEditor-Engine.dll`
(`dumpbin /exports`). Стек: `UWorld::Tick` → тик компонента → `UPhysicalAnimationComponent::UpdateTargetActors` →
`FPhysInterface_Chaos::ExecuteWrite` → статическая `ComputeLocalSpaceTargetTM` (рядом с
`USkeletalMeshComponent::CompleteParallelBlendPhysics`) → assert. По исходнику движка
(`PhysicalAnimationComponent.cpp`): `UpdateTargetActors` копирует `SkeletalMeshComponent->GetBoneSpaceTransforms()` и
читает `LocalTransforms[BoneIndex]` — пустой массив. Пустой он, пока идёт **параллельная** оценка позы меша:
`USkeletalMeshComponent` на время задачи забирает `BoneSpaceTransforms` в контекст оценки (swap буферов), а
пререквизит PAC → меш ждёт только тика меша, не завершения задачи.

* Проверка: `-ExecCmds="a.ParallelAnimEvaluation 0"` + `-BoxPhysHits=1` — 60 с автобоя, 26 попаданий, без падения
  (было: падение на ~20-й секунде).
* H2 (вызовы из тика бойца) — нет: падает тик самого PAC. H3 (LOD) — не нужна.
* Фикс: при включённой физреакции `ABoxerCharacter::InitPhysics` ставит cvar `a.ParallelAnimEvaluation 0` (вся
  анимация — на игровом потоке). Проверено: `-BoxPhysHits=1`, 90 с автобоя (2 раунда, перерыв), 37 попаданий — без
  сбоев. Выключать параллельность только у видимого меша (`UBoxerVisualAnimInstance::CanRunParallelWork`) мало:
  вместо падения — зависание на том же месте (~22-я с). Цена — анимация на игровом потоке (на двух бойцах не замерено).
* По умолчанию физреакция всё равно ВЫКЛ.: реакцию дают пружины костей ([FIGHT_FEEL.md](FIGHT_FEEL.md)).

## 4. Найдено ревью, не исправлено (нужно решение или проверка вживую)

- **`HoldAtEnd` проскакивает окно 0.03 с** (`BoxerCharacter.cpp`, `HoldAt`): при кадре > 33 мс монтаж нокдауна/финала
  уходит в авто-blend-out, лежащий боец «встаёт» в idle. Проверить на просадке fps (`t.MaxFPS 20`). Фикс — выключить
  авто-blend-out у монтажа или паузить с упреждением `pos + dt·rate ≥ target`.
- **Удар в блок ослаблен дважды** (`HitReaction`): `Magnitude` события `Blocked` — уже утечка сквозь блок, код ещё
  умножает на 0.4. Вопрос намерения: импульс в предплечье сейчас почти нулевой. Решить, когда физреакция заработает.
- **`PhysMesh` не переживает пересоздание child actor** — проверка только на null, не `IsValid`. Низкая вероятность.

  Но 0 остановок (KO и RSC-H) на 500 боёв даже для любителей выглядит низко. Сверить с web на тех же бойцах
  до любых правок: ядро совпадает с web на эталонных сидах, правка баланса только здесь = расхождение с web.
- Баланс на 180 с не выверен плейтестом (FIGHT_CORE_PORT.md, упрощение 3) — сначала плейтест на ПК, потом крутить.
